# DHK Paper

Local prototype for a platform-owned virtual trading experience. Every order, fill, balance and position belongs to the platform; live broker order execution is unavailable.

Paper execution uses an explicitly synthetic data source. Instrument prices and contract sizes are illustrative, including NSE equity/futures/options, BSE futures, MSE, MCX, GIFT NIFTY and global samples. All sample values use virtual INR. A separate, read-only Gold API panel displays free public reference prices in USD with provider timestamps and freshness checks; these never price paper orders.

Customer history cannot be reset by customers. An administrator controls market/instrument visibility, free reference-feed visibility and maximum customer accounts (Super Admin and brokers excluded; lowering a cap preserves existing access). Disabled instruments block new entries, including API orders and pending fills; reductions/exits remain allowed. Super Admin creates broker invitations and oversees all accounts. Brokers create single-use user invitations and see only their own users and executed trades. Super Admin can set a separate user-account cap for each broker, in addition to the global cap. Recipients activate their accounts by setting a password, then sign in normally. Each user’s broker assignment is permanent. Super Admin and brokers can disable accounts within their scope; disabling a broker blocks access for all its users. Pre-existing unassigned users retain access and can be assigned once by Super Admin. Customers sign in to their own paper books. The first supported workflow is market watch → order ticket → filled order → position → close → realized P&L. Default virtual capital is ₹1 crore; weekly automatic wipes are disabled.

This first version runs locally with React, FastAPI, Postgres and Redis, reusing OpenBull. Live exchange contract data, native mobile apps, account recovery, representative load validation and public deployment remain future work. Preserve truthful demo labeling throughout.

Each newly executed user buy and sell incurs 4% brokerage on its trade value, allocated 3% to the user's permanent broker and 1% to Super Admin. Virtual user funds and net realized P&L include the charge. Broker/Super Admin earnings are separate virtual balances sourced from an append-only fee ledger. Unassigned legacy users must be bound to a broker before new trading; existing history is not charged retroactively.

CNC delivery orders and T+1 settlement are disabled. Equity defaults to MIS; existing CNC positions are exit-only. MSE, GIFT and Global support NRML entries only because no MIS square-off lifecycle is configured. Settings updates require the complete policy and its revision; stale writes return 409. Production schema migration is an explicit backup-first deployment step.

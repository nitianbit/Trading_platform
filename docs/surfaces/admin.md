# Admin overview

Mode: Operate.

Extend the established DHK Paper slate/indigo system. The administrator monitors all platform accounts in one table, with customer count, open positions, pending orders and fill counts above it. Broker invitations, user management and global paper settings remain the primary Super Admin actions. Brokers see only their own user activity. Numeric columns use tabular figures. The table scrolls horizontally on narrow screens. Loading, failure/retry and no-customer states must remain readable. Uninitialized balances are explicitly labeled; the admin overview never creates balances merely by viewing an account.

The backend owns all aggregate values and enforces admin access. Regular customers return to their trading desk. Values use virtual INR and the persistent shell identifies synthetic prices and paper-only execution.

Platform controls extend this page with a customer-account cap, market and instrument switches, and independent public-reference feed/asset switches. Customer capacity excludes admins and preserves access for existing accounts. The form has explicit saving, success and failure states. Labels explain that hidden instruments still support exits, and live public USD references remain separate from synthetic paper fills. These additions passed build, targeted lint, policy/ledger tests and HTTP integration checks. The 6 November 2026 capture set verifies the repaired Super Admin and broker layouts at desktop (1440×900) and mobile (390×844). Public reference feeds were disabled by test policy; live reference-price rendering remains unverified.

Unsaved platform controls use the existing confirmation-dialog treatment. Attempting another route or Sign out asks “Discard unsaved controls?” with “Keep editing” and “Discard and leave”; keeping the edits leaves the session and form intact, while discarding proceeds with the requested navigation. Browser reload or closing requests the native unsaved-changes warning. A revision conflict blocks another save until “Reload latest controls” succeeds. Reload replaces the complete settings result, including the displayed customer count, and updates the policy, revision and saved baseline together; the success text asks the user to review before saving.

The hierarchy extension adds a Brokers section with username/email invitation creation, copyable links, account status and enable/disable actions. Only Super Admin sees this section and global platform controls. The Users page lets brokers create invitation links and manage only their own users; Super Admin sees every user and can assign an unassigned legacy account once. Ownership controls explicitly say permanent. Invitation acceptance reuses the same slate/indigo form style and shows broker identity, password confirmation, activation success and invalid-link feedback. The November 6 browser evidence covers three-role sign-in, invitation activation/invalid links and logout/login, with stable desktop/mobile captures of manager and invitation states. The final visual repair review returned ship with no remaining scored findings in that scope.

The broker-limit extension adds an inline numeric limit editor to each broker row and a quota indicator on the broker user-invitation form. User trades is a separate table section on both manager overviews, with a user filter and older/newer pagination; Super Admin sees all user fills and brokers see only their own users. It reuses the incumbent tokens and table conventions. Static checks and API authorization tests passed. November 6 manager captures show contained horizontal table scrolling; long broker/user names and screen-reader captions no longer expand the mobile page. These captures do not separately exercise every filter, pagination or empty-state combination.

Brokerage earnings appear as a separate virtual balance on both manager overviews. User trade history includes brokerage, broker credit and admin credit columns; the user Tradebook and CSV expose the same backend-owned fee amounts. The trading desk labels realized P&L as net and shows fees paid. Order tickets disclose the 4% executed-value fee for users before submission. Existing layout conventions remain. November 6 evidence includes manager earnings, user Tradebook and the order ticket on both viewports; the 4% fee and permanent broker hierarchy remain intact.
